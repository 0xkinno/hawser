# Findings on Switch

Every result below comes from a script in `probes/` that writes a dated JSON file to `probes/results/`. The site's findings page renders those same files. Nothing here is taken from the documentation alone.

## How this was run, and what it is not

- Server: a real switch-core 0.31.0, started from the cloned Switch repository (commit 9e158a7) with a local Postgres 16, no Docker, inside a Claude Code cloud session. It is not the Codespace server. A run on the Codespace server is the next step and is listed in `docs/HANDOFF.md`.
- Date: 6 November 2026.
- People: stand-in agents (`master-sim`, `agent-sim`, `charterer-sim`), never real people. Attack messages in the break campaign were scripted, not generated by a model.
- Quoted server text: the refusal and the update notice contain a long dash and an emoji. In this document those two characters are replaced so the page passes the repository's copy check. The JSON in `probes/results/` has the exact text.
- Honesty about the process: the questions come from the build brief, written before any probe ran, but they were not committed as a separate file before the first run. The results were not selected: every probe that ran is listed, including the ones that contradict the brief.

## Unplanned findings

1. **Exclusive role assumed twice at the same instant.** On the first use of a role, two agents calling `assume_role` within 7 ms both received success. The loser found out through `leases/renew` returning `held: false` about 0.5 s later. The Timekeeper now checks the roster after `assume_role` and counts itself active only if it is the sole holder.
2. **The role lease belongs to the agent, not the room.** A second `assume_role` by an agent that still holds a lease elsewhere is refused with `You already hold a role lease; release it before assuming another`, until the old lease lapses.
3. **New agents are owner-only.** Anyone else who addresses a Timekeeper gets Switch's visible refusal, even though the Timekeeper hears the message. Opening the Timekeeper's addressing to the room is required.
4. **Two connections of one agent fight.** The second `connect_to_room` takes over the first connection's claim, and the first connection's operations then fail with `Not connected to a room`.
5. **Sequence numbers sit near 2^53.** Event ids look like generation times 2^20 plus a counter (about 9.007e15). A JavaScript client that parses them as numbers loses precision once the generation rises. The client keeps `id`, `sequence`, `cursor` and `generation` as exact strings.
6. **`/gateway/version` needs a login**, so an unauthenticated version probe fails. The agent bridge reports the version in `connection_state` instead.
7. **A defect in our own reconciler, found by test and fixed.** Berlin repeats a local hour when clocks go back (25 October 2026). The first version parsed such a time as one occurrence and produced 77 false divergences in 16,498 generated events. It now abstains and asks for the offset. Result on the same events: 0 false, 0 missed, 271 abstentions.
8. **A design flaw in our own signing, found by the end to end run and fixed.** Signer remarks were folded into the digest, so one person signing with remarks voided the others. Remarks now stay on that signature.

## For the friction report

The accurate form of the document finding is: room documents keep no revision history, and an update posts a one line notice that does not say what changed, so other members cannot see what a company rewrote. The Timekeeper anchors a fingerprint of every revision in the room's own record to cover that. The earlier plan said "no event is emitted". That was wrong, and the submission text uses the corrected form.

The agent protocol page describes SSE plus a 2 second beat. The live transport is the WebSocket with a 10 second server ping. A client written from the page lands on the compatibility path.
